# Changelog

All notable changes to OpenCode-Hi are documented here.

## Unreleased
- Drops only the process-local child callback index when OpenCode confirms `session.deleted` after a Mission has already STOPped (and on cancelled/stale callback fences). Late deletion no longer leaves a dead Worker lookup for the plugin lifetime, while canonical stopped Task/Worker outcomes remain immutable.
- Scopes in-flight Worker spawn deduplication to the exact Hi Mission. Identical task contracts in different parent sessions can no longer collapse onto one native child Worker; same-Mission fingerprint dedupe remains intact as an ephemeral spawn optimization.
- Fences OpenCode native permission reconstruction state by exact session lifecycle. Pending permission patterns are now keyed by `sessionID + permissionID`, permission persistence occurs only after current Mission/Worker lifecycle guards, and stopped/completed/deleted/disposed missions clear their process-local entries. Late `permission.asked`/`permission.replied: always` events after STOP can no longer retain stale patterns or create persistent Hi project authority.
- Refreshes the Hi-owned local preview lease when a live visual Task's bounded scope changes. Same-task preview reuse now requires the same canonical root **and** canonical scope policy, so a resumable Task that accepts a bounded scope expansion cannot keep serving through a stale loopback-server closure that rejects the newly admitted target (or preserves an obsolete access policy).
- Fixes a bounded browser lifecycle leak on child idle settlement failure: if assistant-result reconciliation throws after host idle acceptance, Hi now cleans the exact Task/Worker Playwright execution owner before marking the Worker failed and cleaning its workspace, matching the existing terminal/cancel cleanup boundary and preventing an unreachable live browser handle from lingering until plugin disposal.
- Tightens zero-known-defect certification truth: the living defect-closure producer no longer stamps an unproven `adjacent-reaudit` step onto every historical defect. Current development certifies the source-bound 11-step closure it actually records, marks repository-wide same-defect-class recurrence as **not certified without an explicit sweep** (predicates, hit dispositions, and guardrail proof), and moves the exact zero-defect receipt assertion behind the evidence-readiness tier instead of letting stale external T3 evidence masquerade as active product acceptance.
- Reconciles OpenCode provider membership before child-model routing: when OpenCode exposes an explicit `connected` provider set, current `dev` now intersects directory `/api/model` rows with that set before supplementing any connected provider absent from the scoped projection. This prevents disconnected/disabled providers leaked by the experimental model projection from bypassing OpenCode `enabled_providers`/provider availability while preserving scoped model filtering inside connected providers.
- Fixes live child-model inventory completeness when OpenCode exposes a connected provider through the provider surface but omits that provider from the directory-scoped `/api/model` projection. Current `dev` keeps `/api/model` authoritative for model membership inside providers that remain connected, supplements only connected providers absent from that scoped surface, never resurrects models filtered from an already represented connected provider, and keeps the scoped inventory usable if provider-state reading fails. No Hi-owned provider/model catalog is introduced.
- Removed dead source-checkout `--team-mode`, `--team-max-members`, and `--team-wall-minutes` writers. Existing legacy `teamMode` data is preserved as unknown file content during unrelated supported updates but is never projected into canonical runtime config.
- Removed five inert legacy model-routing leaves (`models.mode/default/roles`, `routing.strategy`, `routing.categoryModels`) from canonical resolved configuration and the option catalog. Older input names remain diagnostic-only at the compatibility boundary and never become routing authority.
- Consolidated the compatibility `hi_role_models` set/clear path behind the same canonical role-model mutation policy used by `hi_settings`; the legacy tool ID/list response remains available, but it no longer owns a second live model-validation/persistence implementation. Current `dev` exposes 35 `hi_*` tools while immutable published `0.2.4` evidence remains 34.
- Removed an Evidence freshness duplicate-truth edge: verification/status/runtime projections now derive freshness from current canonical Evidence items, and persisted `execution.evidence.fresh` is validated as cache-only so a forged/stale boolean cannot satisfy verification without Evidence.
- Consolidated scheduler capacity ownership: production TaskRuntime now derives all active global/provider/model occupancy from durable Mission scheduler reservations and uses only a stateless policy source for limits, removing the duplicate process-local allocation backstop while preserving OpenCode child/session execution ownership.
- Makes accepted dispatch backpressure restart-safe without adding a second queue database: a sessionless `queued` Task/Worker with its durable `ExecutionProfile` remains canonical pending work across restart, the process-local queue is rebuilt only as a scheduling cache after workspace/process/browser reconciliation, `waiting-user` pauses retain queue identity, and bounded-Playwright work revalidates live browser capability before child creation.
- Preserves accepted queued work across semantic no-op user interaction: sessionless queued workers are paused in place while follow-up meaning is pending, never dispatched through the semantic gate, rebound to the new generation only for `non-material`/`resume`, and still invalidated for material verification/amendment changes; queued constraint work reuses the existing deferred constraint-update path before dispatch.
- Repository exploration ambiguity clearance is now evidence-bound and freshness-aware: `DONE` alone cannot unlock implementation; Hi requires same-attempt OpenCode read receipts, explicit bounded source provenance, `context_gap: none`, and (for contract-critical ambiguity) a read-grounded decision claim. Source drift blocks implementation until bounded exploration is refreshed; read/decision claims are not promoted to verification or authority.
- Adds evidence-bound prior Task outcome memory as a narrow project-scoped derived receipt log. Hi recalls at most three prior non-DONE outcomes only when structured task/dependency shape and exact current source bytes still match; only runtime-receipted machine failure classes are retained, a later matching `DONE` supersedes older failure hints, provider/permission/capability availability failures are excluded, and the optional handoff hint is explicitly advisory/non-Evidence with no routing, model-reputation, Authority, verification, or completion power. The log is bounded to 128 records, symlink-confined to the project, contains no raw WorkerResult/provider prose, and bookkeeping failures cannot block Task settlement.
- Diagnosis/root-cause completion now requires an evidence-bound falsifiable hypothesis contract: parent prose alone cannot synthesize passed diagnostic evidence, `SUPPORTED` requires fresh terminal canonical Evidence refs, and `FALSIFIED`/`INCONCLUSIVE` hypotheses remain durable ledger history without closing analysis. Correlation-based task/model/environment failures still do not create harmful project-methodology learning.
- Adds advisory counterfactual decision-stability diagnostics to the host-neutral semantic execution decision. Hi evaluates a bounded set of valid one-step structured intent neighbors and reports which decision axes (execution path, topology, team, model class) change. This is local sensitivity, not probability/confidence, and never becomes routing, authority, verification, or completion authority. External-action authority invariants are preserved in counterfactual generation.
- Adds benchmark-gated atomic context projection for Hi-owned child handoffs. The selector uses existing explicit/runtime metadata (priority, freshness, protection and whole-group cost), preserves caller order when utility is equal, deduplicates byte-identical optional groups, never partially emits an atomic group, and fails closed if protected/required context cannot fit the real 5,000-character Worker relevant-context consumer budget. OpenCode remains canonical history owner; this does not add a second memory/history database or hidden LLM relevance ranking.
- Adds advisory stochastic-evaluation uncertainty diagnostics to comparative benchmark certification: sample standard deviation and 95% t-interval for current wall time, optional Fleiss kappa from an explicitly supplied fixed-width binary judge matrix, and optional evidence-family diversity from explicit family labels. Exact benchmark receipts, deterministic checks, outcome stability and environment identity remain canonical verdict authority; LLM/judge consensus cannot turn a deterministic pass into failure or a stable regression into success, and missing eval metadata is reported rather than inferred.
- Adds causal compute/context attribution as a derived economics diagnostic over canonical Worker attempt usage and the Mission lifecycle ledger. Repeat execution is separated into corrective retry, behavioral model escalation, provider runtime fallback, write-conflict reconciliation, constraint rebase, semantic follow-up resume, restart reconciliation, or explicit unattributed repeat. Exact complete token/context volume and monetary provenance remain source-bound; Hi does not label context volume as provider cache repayment or avoidable cost without per-turn prefix/TTL evidence, and attribution never becomes routing authority.
- Adds revision-bound user Constraint/Decision atoms on top of the existing semantic follow-up/rebase lifecycle. Structured atoms carry subject/predicate/polarity/scope, explicit supersession lineage and USER authority; opposite active atoms fail closed instead of silently applying latest-text-wins. Active `DENY mutate path` atoms block write-capable task scope admission and turn prohibited worker/native-diff mutations into `FIX_REQUIRED` constraint violations. Legacy prose constraints remain a compatibility projection, and read-only inspection is not blocked by mutation-only constraints.
- Project methodology learning now keeps evidence-bound independent observations but gates runtime admission with a deterministic Beta-posterior confidence and frequency-aware freshness decay; historical READY maturity no longer makes stale learned HOW permanently active, and fresh exact evidence can restore admission without turning task failures into unproven negative causality.

- Adds a unified project settings control plane. Runtime `hi_settings` shows only OpenCode-owned effective connected models and can atomically change Work Mode (`Adaptive`, `Single`, `Multi`), child-role model/fallback preferences, and execution limits. A rejected multi-field request performs no partial write; `visual-qa` remains vision-gated; successful project settings reload immediately for new worker dispatches without changing OpenCode-owned primary Manager/Working Manager model selection. Legacy `hi_role_models` remains a compatibility surface. When explicit project settings do not yet exist and live models are available, the first pending chat session receives one bounded onboarding projection; material work is not interrupted and continues with Adaptive + Automatic defaults. Opening the settings surface explicitly refreshes OpenCode runtime inventory so newly connected providers appear without relying on unsupported host events. Settings-only chat requests now stay on the settings control plane instead of becoming execution missions; OpenCode-style nested tool arguments are normalized for mutations, and the natural-language `review` role maps to canonical `qa-reviewer`. Adds strict `routing.allowedModels` as one global child-model allowlist so Adaptive can be constrained to an exact connected-model set without duplicating six role mappings. Allowlist order is not routing priority; Adaptive selection inside the allowed set remains capability/role driven. Single Work Mode now resolves effective primary behavior to write-capable `working-manager` while preserving any saved `manager` preference for non-Single modes. Standalone visual surfaces can now use fresh scope-bound canonical `visual-evidence` as stronger proof for `changed-surface-sanity` when no repo-native verifier exists; raw browser observations, screenshots, or worker prose still cannot satisfy verification.
- Adds a mission-scoped behavioral model hazard circuit without turning telemetry into routing authority. Recovery identity now ignores activity-only attempt/status churn; after an initial worker attempt plus two bounded same-session/same-model corrective attempts still yield no semantic gain, Hi can use one fresh capability-ranked recovery-only candidate that is revalidated against the live OpenCode inventory, strict allowlist, role capabilities and scheduler. Normal provider fallback remains host-terminal-only; explicit per-task model ownership cannot escape to an unconfigured automatic model; ambiguous recovery dispatch remains quarantined rather than replayed. Unparseable child prose still fails the strict WorkerResult parser, but host settlement now classifies that exact contract failure as `FIX_REQUIRED` so the same bounded correction/hazard ladder can recover it instead of terminally killing the task; model-identity verification remains fail-closed.
- Adds `npx opencode-hi config` as the simple project settings CLI for Work Mode, execution limits, role mappings, reset-to-Automatic, and read-only settings inspection. Offline CLI model IDs remain explicit preferences only; live availability validation belongs to runtime `hi_settings` and OpenCode inventory truth.

## 0.2.4

- Simplifies normal setup/reconfigure UX: the terminal wizard now asks only which primary behavior to use (`Auto`, `Working Manager`, or `Manager`). Topology, execution profile, parallelism, and specialist thresholds remain internal Hi runtime policy rather than normal-user setup questions; legacy cost/quality routing strategy fields remain compatibility diagnostics rather than model-selection authority.
- Adds chat-native `hi_role_models` configuration. From an OpenCode conversation, “Hi rol modellerini ayarla” lists only the effective runtime models and persists explicit child-role model/fallback choices for `coder`, `architect`, `repository-explorer`, `qa-reviewer`, `security-reviewer`, and `visual-qa`. On exact OpenCode 1.18.21, Hi prefers the directory-scoped `/api/model` available/enabled model surface over the broader connected-provider catalog, including an authoritative empty result; it falls back to the connected-provider catalog only when that scoped API is unavailable. `visual-qa` rejects non-vision models; primary Manager/Working Manager model ownership remains OpenCode-native.
- Adds an OpenCode upstream-churn gate instead of treating every patch release as a full re-certification restart. The exact SDK/plugin build target remains source-controlled, while `host:check-update` / `host:observe-update` compare the three stable registry identities, bind exact upstream tags, classify changed host paths into capability surfaces, fail closed on registry skew or unclassified critical changes, and never auto-promote support. Release preflight now rejects a stale exact target before publication work. Exact host binary integrity comes from a committed immutable-release asset manifest instead of per-script version/SHA hardcodes. The 0.2.4 candidate is currently aligned to OpenCode `1.18.21`; the measured 1.18.20→1.18.21 delta affects provider runtime and session lifecycle, requiring fresh-consumer plus process/workspace consideration rather than unrelated browser re-certification. Historical `0.2.3` / OpenCode 1.18.19 evidence remains immutable provenance.
- Makes child-model ownership explicit and deterministic: explicit task model → ordered Hi role mapping → explicit OpenCode agent model → ephemeral capability/variant recommendation. Automatic recommendations are never persisted; cost/quality/feedback remain telemetry and cannot silently rerank explicit preferences or normal automatic selection.
- Fixes forced `Manager` mode for small local implementation work: because Manager is read-only, Hi now plans a `coder` child instead of producing a zero-child non-direct execution state.
- Reduces orchestration/context ceremony on the minimum-sufficient path: terminal child waits now return one canonical control decision with repo-native verification-route availability, so an unavailable verifier no longer triggers redundant reads, shell checks, direct-progress calls, context-artifact writes, or a second child. Child handoffs are consumer-specific task deltas rather than repeated control/methodology boilerplate, while evidence, authority, exact-attempt, dirty-work and STOP fences remain mechanically enforced.
- Deduplicates semantically identical fresh context artifacts by content plus provenance/producer identity and reuses the same Mission handle; stale or provenance-distinct observations remain separate and cannot be silently revived as fresh.
- Makes DAG handoff a bounded graph dataflow instead of a parent polling/retrieval ceremony: a successor receives only direct completed dependency outcomes at actual dispatch time, bound to exact worker attempt/run/generation and accepted-result digest. Dependency output is explicitly non-Evidence, is revalidated after child creation and before prompting, and stale/corrupt provenance fails closed.
- Hardens parallel admission for uncertain write ownership: two write-capable tasks are no longer treated as independent when either mutable scope is unknown. Known-disjoint writers may still run in parallel without mandatory worktree overhead; overlapping or unknown writer surfaces serialize, while read-only unknown surfaces may still fan out. Existing explicit workspace isolation keeps exact baseline/lease/reintegration safety rather than becoming a blanket per-task worktree policy.
- Hardens provider fallback ownership: OpenCode remains the sole owner of transient provider retry/backoff, while Hi only switches an explicitly allowed child model after host-terminal failure. An uncertain fallback-prompt acknowledgement is no longer downgraded to a terminal failure; the possibly-live recovery child and its exact scheduler reservation remain quarantined, and the mutating prompt is never replayed speculatively.
- Bounds OpenCode `prompt_async` host-acceptance acknowledgement without taking over provider execution: Hi waits at most 15 seconds for the immediate mutation acknowledgement, abort-signals the SDK request when that consumer deadline expires, treats SDK `{error}` result tuples as rejection, and never replays the mutating prompt through a sync endpoint or alternate model. Existing exact child/session abort-or-quarantine fencing remains the owner after ambiguous dispatch.
- Fences same-session stale terminal callbacks with exact OpenCode message ancestry instead of adding a polling/history owner. Every Hi Worker attempt supplies its own OpenCode-compatible user `messageID`; assistant settlement rejects a different `parentID` (with creation time as a secondary stale fence) before usage/error/model/result mutation. Exact duplicate prior WorkerResults are also rejected before scheduler settlement, so an old callback cannot move a newer reservation from `RUNNING` to `SETTLING`. OpenCode remains the owner of session history and live status.
- Hardens required independent-review provenance: a reviewer PASS can close a high-risk review obligation only when it is bound to the canonical reviewer role, exact reviewer worker/source, child session, native source-state hash, task, generation, and execution attempt. Persisted/unbound, coder-impersonated, wrong-state, or stale-attempt reviewer claims remain readable for compatibility but cannot certify completion; relevant later mutation invalidates the review and reopens assurance.
- Replaces flat destructive-shell matching with a bounded execution-semantic projection for safety classification: nested shell/process substitutions, transparent and shell wrappers, CWD-changing flows, `find`/`xargs`/bounded `parallel`, literal interpreter execution, PowerShell recursion, and nested external effects are classified by executable meaning while inert quoted/heredoc text remains data. OpenCode permission ownership and Hi authority/staging/user-dirty ownership are unchanged; ambiguous destructive execution fails closed, and ordinary structure-free commands take a low-cost fast path.
- Tightens adaptive verification economy for bounded local review: model-inferred code-test/build checks no longer become mandatory merely because the host primary suggested them. Low/medium-risk review defaults to canonical `review-evidence` (plus surface-specific visual verification when applicable), while an exact user-named verifier command remains authoritative and high-risk work may still widen verification. Direct low-risk review no longer exposes an independent-review gate unless policy actually requires independence; canonical direct-review completion returns terminal `STOP`, redundant progress is idempotent, and late host progress/diff/idle callbacks cannot mutate the completed mission. The same verifier-admission rule applies to verification follow-ups, and plain-text `.txt` files are retained as exact semantic targets.
- Extends comparative benchmark certification with failure stability and environment attribution without introducing another runtime owner: real-host failures require three identical behavior fingerprints under one environment identity before they can be called stable regressions; divergent samples are `FLAKY`, deterministic fixtures avoid the three-sample tax, environment/authority blocks remain separate, and source/fixture/config/host/model/runtime deltas are reported without fabricating a singular cause when multiple classes changed.
- Hardens implementation-obligation traceability without adding another planner/state owner: exact user-grounded material targets are retained on the existing implementation obligation, and parent-direct, worker-result, automatic post-verifier reconciliation, plus final completion all require those targets to be covered by the observed changed-file surface. Model-only or verifier-only paths do not become must-have implementation targets; terminal prose punctuation is canonicalized before target binding; resolved semantic assessments that contradict their local/multi-file material-target shape fail closed (with explicit TDD retaining its source-plus-test local work-unit exception).
- Makes independent-review freshness coherent across completion and control projection without adding polling/watch ownership: the existing bounded reviewer `scope_state_hash` is revalidated against current scoped bytes at completion, gate/readiness, continuation, system-projection, tool and reviewer-settlement decision boundaries. An external same-path byte mutation therefore makes prior reviewer evidence stale even if no Hi mutation event fired; closed structural obligations cannot hide missing current evidence. Request-local claim reuse avoids duplicate hash passes inside one completion decision, while cross-check/global memoization is intentionally avoided so freshness is not weakened by a stale cache or a wider TOCTOU window.

## 0.2.3

- Fixes a verification freshness race where invalidated evidence and its fresh replacement could share one millisecond timestamp; invalidated evidence is now excluded from verification candidate selection. Also makes Playwright cache-path regression assertions platform-neutral on Windows.
- Bounds verification/completion recovery when a required runtime capability is unavailable: mandatory visual/browser, MCP, model-dispatch, workspace, process, dependency and session-abort failures now resolve to durable terminal operational state instead of feeding unchanged synthetic continuations.
- Routes `visual-check` through the canonical visual methodology/browser preflight, keeps verification evidence-owned, and makes `hi_direct_progress` return `EVIDENCE_REQUIRED` for verification obligations instead of allowing prose to close them.
- Adds one-shot Chromium self-healing for the Hi-owned Playwright surface using pinned `playwright-core@1.62.1`, a Hi-owned platform cache, bounded bootstrap time, and failure deduplication; unavailable bootstrap remains an explicit environment/capability blocker rather than a retry loop.
- Makes child-result parent wake re-enter the canonical completion/continuation evaluator and hardens failed process lifecycle/abort paths so unverified native ownership cannot masquerade as healthy `WAIT`.
- Adds a Node-native project-control UX for the `0.2.3` candidate: `install` now safely ensures setup/update ownership; terminal `setup`/`install` runs a bounded canonical-policy wizard; `reconfigure` reopens it; and `state`, `reprofile`, `roles`, `rotate`, and `check-update` expose bounded common configuration without hidden postinstall mutation or provider credential ownership. CI/non-TTY setup remains deterministic via automatic detection or `--non-interactive`.
- Adds `npm run release:preflight -- --sha <exact-HEAD>` as a fail-closed, read-only candidate check for clean SHA/version/tag/npm/pack identity; it never tags, pushes, creates a GitHub Release, or publishes. Local preflight uses the canonical release Python environment when available and accepts committed evidence projections across later `data/validation/**`-only attestation commits while still rejecting any intervening source/docs/package/runtime drift.
