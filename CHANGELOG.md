# Changelog

All notable changes to OpenCode-Hi are documented here.

### Fixed — grounded TDD authority projection
- Stop `intent.tdd` from granting `test-authoring` write authority inside the raw semantic parser before user-text reconciliation. Hi now derives implicit test-authoring only after the TDD signal is grounded against the actual initial or follow-up user text, while explicit `required_capabilities` / capability request-unit ownership remains authoritative.
- Added regressions proving generic test/verify or contradictory TDD signals create neither TDD methodology nor durable test-authoring capability/obligation, while explicit test-first requests and explicit test-authoring capability still retain canonical ownership.

### Fixed — queued reconciliation control priority
- Prevent a sessionless queued worker from masking an older `FIX_REQUIRED`/reconcilable task result when the parent reaches idle. Live `created`/`starting`/`busy` children still retain WAIT priority, while queued-only state now yields to parent reconciliation before returning to WAIT, avoiding a durable no-actor deadlock without weakening mutable-surface scheduler serialization.
- Added regression coverage for both the exact queued-plus-unreconciled deadlock and the guard that a genuinely live child still wins WAIT.

### Fixed — bounded busy/no-progress child recovery
- Preserve generic OpenCode `busy`/`retry` as healthy live execution by default, but after three same-attempt `hi_task_await` timeouts spanning the existing 120-second no-progress window with no later assistant/tool progress, expose one explicit `hi_task_cancel` recovery route for that exact stalled worker. Fresh child activity invalidates the stall evidence, so healthy long-running work remains protected.
- Prevent `hi_context_artifact_add` from accepting canonical `*-evidence` kinds; context artifacts remain context-only and cannot substitute for worker/host verification or review evidence.

### Fixed — Scenario 05 review authority settlement
- Materialize a canonical `review` obligation whenever the resolved verification policy requires independent review, including authority-boundary remediation/security-review missions. This keeps external-action authority separate while giving fresh reviewer evidence an exact assurance/verification claim to close instead of ending in `review-obligation-missing`.
- Claim-link independent reviewer tasks to an open verification obligation when that exact verification contract requires `review-evidence`, while keeping unrelated technical/visual evidence off the reviewer execution contract. This lets one fresh source-bound reviewer observation satisfy both assurance and verification provenance without prose/context-artifact promotion.
- Make semantic review explicitly report-only and classify review-plus-remediation as write-capable bug-fix/implementation work while retaining specialist review ownership.
- Keep unavailable native process-lifecycle support task-local for obligation/evidence-free auxiliary process workers, so an optional PTY path cannot spuriously force the whole mission into user-action wait.
- Ignore reviewer-shaped `findings[]` emitted by non-reviewer workers before canonical normalization so unauthorized metadata cannot poison task liveness or scheduler admission.
- Compare canonical reviewer finding projection semantically rather than by JSON object key insertion order while preserving fail-closed loss/evidence-binding checks for real reviewer roles.


### Fixed — Scenario 05 parent shell ownership guard
- Treat inline interpreter execution (`python -c`, `node -e`, shell `-c`, and equivalents) as mutation-capable at Hi mission ownership boundaries unless it is a canonical verification invocation. This closes a parent parallel-topology bypass where a multiline Python payload could mutate the fixture while being recorded as read-only review input.
- Added regression coverage for the exact multiline Python write shape and preserved admitted parent verifier commands such as `python3 -m pytest`.


### Fixed — nonvisual semantic request-trace contract
- Aligned the provider-visible semantic assessment gate with the parser's visual-only request-unit trace contract: `verification_cases` / `nonvisual_request_units` partitioning is required only for `visual-check`, while nonvisual missions must leave both arrays empty.
- Made accidental nonvisual RU partitioning fail with actionable `nonvisual_request_units=[]` guidance and added regression coverage for a pure nonvisual security assessment.

## 0.2.4

- Adds an OpenCode upstream-churn gate instead of treating every patch release as a full re-certification restart. The exact SDK/plugin build target remains source-controlled, while `host:check-update` / `host:observe-update` compare the three stable registry identities, bind exact upstream tags, classify changed host paths into capability surfaces, fail closed on registry skew or unclassified critical changes, and never auto-promote support. Release preflight now rejects a stale exact target before publication work. Exact host binary integrity comes from a committed immutable-release asset manifest instead of per-script version/SHA hardcodes. The 0.2.4 candidate is currently aligned to OpenCode `1.18.21`; the measured 1.18.20→1.18.21 delta affects provider runtime and session lifecycle, requiring fresh-consumer plus process/workspace consideration rather than unrelated browser re-certification. Historical `0.2.3` / OpenCode 1.18.19 evidence remains immutable provenance.
- Makes child-model ownership explicit and deterministic: explicit task model → ordered Hi role mapping → explicit OpenCode agent model → ephemeral capability/variant recommendation. Automatic recommendations are never persisted; cost/quality/feedback remain telemetry and cannot silently rerank explicit preferences or normal automatic selection.
- Fixes forced `Manager` mode for small local implementation work: because Manager is read-only, Hi now plans a `coder` child instead of producing a zero-child non-direct execution state.
- Reduces orchestration/context ceremony on the minimum-sufficient path: terminal child waits now return one canonical control decision with repo-native verification-route availability, so an unavailable verifier no longer triggers redundant reads, shell checks, direct-progress calls, context-artifact writes, or a second child. Child handoffs are consumer-specific task deltas rather than repeated control/methodology boilerplate, while evidence, authority, exact-attempt, dirty-work and STOP fences remain mechanically enforced.

- Makes DAG handoff a bounded graph dataflow instead of a parent polling/retrieval ceremony: a successor receives only direct completed dependency outcomes at actual dispatch time, bound to exact worker attempt/run/generation and accepted-result digest. Dependency output is explicitly non-Evidence, is revalidated after child creation and before prompting, and stale/corrupt provenance fails closed.

Known-disjoint writers may still run in parallel without mandatory worktree overhead; overlapping or unknown writer surfaces serialize, while read-only unknown surfaces may still fan out. Existing explicit workspace isolation keeps exact baseline/lease/reintegration safety rather than becoming a blanket per-task worktree policy.
- Hardens provider fallback ownership: OpenCode remains the sole owner of transient provider retry/backoff, while Hi only switches an explicitly allowed child model after host-terminal failure. An uncertain fallback-prompt acknowledgement is no longer downgraded to a terminal failure; the possibly-live recovery child and its exact scheduler reservation remain quarantined, and the mutating prompt is never replayed speculatively.
- Bounds OpenCode `prompt_async` host-acceptance acknowledgement without taking over provider execution: Hi waits at most 15 seconds for the immediate mutation acknowledgement, abort-signals the SDK request when that consumer deadline expires, treats SDK `{error}` result tuples as rejection, and never replays the mutating prompt through a sync endpoint or alternate model. Existing exact child/session abort-or-quarantine fencing remains the owner after ambiguous dispatch.
- Fences same-session stale terminal callbacks with exact OpenCode message ancestry instead of adding a polling/history owner. Every Hi Worker attempt supplies its own OpenCode-compatible user `messageID`; assistant settlement rejects a different `parentID` (with creation time as a secondary stale fence) before usage/error/model/result mutation. Exact duplicate prior WorkerResults are also rejected before scheduler settlement, so an old callback cannot move a newer reservation from `RUNNING` to `SETTLING`. OpenCode remains the owner of session history and live status.

Persisted/unbound, coder-impersonated, wrong-state, or stale-attempt reviewer claims remain readable for compatibility but cannot certify completion; relevant later mutation invalidates the review and reopens assurance.

OpenCode permission ownership and Hi authority/staging/user-dirty ownership are unchanged; ambiguous destructive execution fails closed, and ordinary structure-free commands take a low-cost fast path.

Low/medium-risk review defaults to canonical `review-evidence` (plus surface-specific visual verification when applicable), while an exact user-named verifier command remains authoritative and high-risk work may still widen verification. Direct low-risk review no longer exposes an independent-review gate unless policy actually requires independence; canonical direct-review completion returns terminal `STOP`, redundant progress is idempotent, and late host progress/diff/idle callbacks cannot mutate the completed mission.
